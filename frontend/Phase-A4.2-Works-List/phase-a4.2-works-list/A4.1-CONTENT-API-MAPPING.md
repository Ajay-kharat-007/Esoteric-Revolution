# Phase A4.1 Content API Mapping

## Works list contract

`GET /api/v1/admin/works` requires Bearer authentication and Admin role. It accepts no query parameters and returns an envelope whose `data` is an array ordered by `updatedAt desc`. Each row contains the complete Work scalar fields, `language`, nullable `publishedVersion`, and `_count: { versions, modules }`. There is no backend pagination, server search, status filter, language filter, assignee projection, current draft title projection, or workflow stage projection.

## Authoring contracts

- POST `/admin/works`: slug, languageCode; optional title and summary. Creates Admin assignment and optional v1.
- GET `/admin/works/:id`: versions, assignments, ordered modules and lessons with latest lesson version.
- PATCH `/admin/works/:id`: slug and introduction-video metadata.
- POST `/admin/works/:id/versions`: title, summary, optional subtitle, description, content, preview.
- POST `/admin/works/:id/modules`; PATCH `/admin/modules/:id`.
- POST `/admin/modules/:id/lessons`; GET/PATCH `/admin/lessons/:id`; POST lesson versions.
- GET `/admin/media`; POST presign; PUT placeholder upload; POST complete.

## Editorial contracts

Submit review, schedule, publish, archive and corrections operate on `/admin/works/:id/*`. Publication preflight is `/admin/rights/preflight/:workId` and requires version, active cleared rights, verified claims, and approved workflow.

## Delivery decision

A4.2 performs client-side search/status/language filtering over the exact list response. It does not claim backend pagination. The Create and Open actions remain visibly deferred until A4.3 and A4.4.
