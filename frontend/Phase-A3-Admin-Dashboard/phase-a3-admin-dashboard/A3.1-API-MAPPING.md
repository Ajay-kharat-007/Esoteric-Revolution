# Phase A3.1 Dashboard API Mapping

- `GET /api/v1/admin/dashboard`: generatedAt, roles, queues (works, support, reports, products, users).
- `GET /api/v1/admin/reports/overview`: generatedAt, users, activeUsers, publishedWorks, paidOrders, activeEntitlements, openSupportCases, openReports.
- `GET /api/v1/admin/audit-events`: most recent 200 audit records; frontend displays first 6.
- `GET /health/ready`: readiness plus database and Redis checks.
  All Admin endpoints require bearer authentication and Admin role. The health endpoint is public. There is no dedicated dashboard recent-activity or system-notices endpoint; audit events are the traceable activity source. Internal Prometheus metrics require `x-internal-key` and are intentionally not exposed to the browser.
